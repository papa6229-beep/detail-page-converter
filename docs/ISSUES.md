# 50개 실전 검토 — 받은 문제들

한 건씩 받아 적는다. **모아서 한 번에 고친다** — 하나씩 고치면 원인이 뭉치는 것을
못 보고 규칙이 서로 부딪힌다(옵션 순서 매칭에서 실제로 그랬다).

받는 형식: `상품번호 / 색 / 변환된 HTML / 원본 스샷 / 무엇이 이상한지`
원인은 이쪽에서 찾는다.

상태: `열림` 받아 적음 · `묶음` 원인이 다른 건과 같음 · `고침` 패치됨

## 고치는 절차

**테스트 76개는 내가 상상한 경우만 지킨다.** `option_tag` 한 줄을 고쳤을 때
테스트는 전부 통과했는데 옵션 사진 배치가 무너졌다(`e02a404` 로 되돌림).
그래서 **실물 50개를 매번 다시 돌려 견준다.**

```
0단계  기준선     문구 자동 채우기를 끄고 49개 변환 → zip                        ✔ 끝
                  python compare_runs.py save 기준선.zip docs/baseline.json
1단계  색·게이트   결과물을 안 만드는 코드만 손댄다 → 견주면 0건이어야 정상        ✔ 끝 (0건)
2단계  한 곳씩     한 군데 고침 → 49개 재실행 → 견줌 → 의도한 상품만 달라졌나
       2-1 옵션값 코드 꼬리 벗기기                                        ✔ 끝 (17개만 달라짐)
       2-2 말머리를 문장으로 안 세기 · 별표를 길이에서 빼기                    ✔ 끝 (1개만 달라짐)
3단계  보류한 것   근거가 모자란 것들. 기준선이 생긴 뒤 다시 본다
```

**49개를 다시 돌리는 일은 이제 이쪽에서 한다.** 리눅스에서 돌린 49개가 윈도우에서
만든 기준선과 **뼈대까지 완전히 일치**하는 것을 확인했다(49/49). 사장님 손이
필요한 것은 새 문제를 발견해 주실 때뿐이다.

매 회차:

```
python compare_runs.py docs/baseline.json 이번회차.zip
```

**고치려던 상품만 달라졌으면 통과. 아니면 그 커밋을 되돌린다.** 설명하고
넘어가지 않는다. 통과하면 `baseline.json` 을 새로 박고 다음 단계로 간다.

기준선은 **자동 채우기를 끄고** 만든다(화면의 `문구는 원본 그대로` 체크박스).
모델 문구는 돌릴 때마다 조금씩 달라서, 켜 두면 50개가 전부 "달라짐" 으로 뜨고
우리 코드가 바꾼 것이 그 안에 묻힌다. 끄면 같은 상품은 몇 번을 돌려도
**한 바이트도 안 달라진다**(5개 상품으로 확인함).

### 기준선 49개에서 잰 것 (표본 5개로는 안 보이던 것)

```
옵션 카드가 있는 상품               20/49
  사진이 붙은 카드가 있는 상품         3     ← 그런데 이 셋이 #10 세트 상품(옵션이 아니어야 할 것)
  전부 빈 카드                      17     ← 진짜 옵션 상품의 대조 성공률 0
광고컷이 2조각 이상 흩어진 상품        2     ← 2495239(5조각) 2495240(7조각) — #11
타이핑 글 + 그림뿐 (hero intro foot)  8     ← #2 · #3 · #5 유형
특징 구간이 아예 없는 상품            15
```

**옵션 대조 실패가 이 데이터의 최대 결함이다.** 원인은 하나다 — 엑셀 옵션값에
붙은 모델코드·바코드. 779행 전체로 재보면:

```
옵션값 892개 (257개 상품)
  코드·바코드 꼬리가 붙은 것          532개 (60%)
  꼬리를 벗겼더니 빈 값이 되는 것        0개
  벗겼더니 같은 상품 안에서 겹치는 것     0개
```

빈 카드 17개 상품의 옵션값 48개로 대조해 보면 **지금 0개 → 벗기면 38개**가 붙는다
(17개 상품 중 13개가 완전히 해결). 남는 4개는 원인이 다르다 —
셋은 상세페이지에 말머리가 아예 없고(통이미지 안에 라벨이 그림으로 박힘),
하나는 #1 의 복수 옵션 말머리다.

`S`/`M`/`L` 이 날아갈까 걱정했으나 실제 데이터에서는 안 일어난다. 벗긴 뒤 3자
이하로 남는 192개는 전부 `역바니` `소프트` `하드` `관통` `비관통` 같은 멀쩡한
낱말이다 — 규칙이 낱말이 아니라 **코드 꼬리만** 떼기 때문이다.

→ **표본 5개일 때 "위험하다"고 미뤄둔 판단을 뒤집는다.** 근거가 892개로 늘었다.
   찍는 것과 보고 긋는 것의 차이가 이것이다.

### 지금 손대지 않기로 한 것

근거가 모자라서 미루는 것이지 못 고치는 것이 아니다.

- **여백 비율로 통이미지 가르기** — #11 에서 반례가 나왔다(버진루프보다 여백이
  많은데 통으로 써야 한다). 단독 기준으로 쓰지 않는다
- **`by` 로 긴 상품명 자르기** — 사례가 #2 하나뿐이다
- **`복시`/`보쿠` 표기 어긋남** — 한 번 넣었다가 되돌린 자리(`e02a404`).
  기준선이 있을 때 마지막에 본다

옵션값의 코드 꼬리 벗기기는 **보류에서 뺐다** — 위의 측정 결과 참조.

## #1 · 2497907 · 그린 · 열림

바니걸 4종. 옵션마다 사진이 여러 장이고, **설명 하나가 두 옵션에 걸친다.**

```
[01. 츤데레 바니· 03. 덜렁이 바니] 두 모델은 따스함이 느껴지는 오렌지 베이지 컬러입니다…
[02. 갸루 바니· 04. 역전 바니] 해당 모델들은 귀여운 핑크 컬러를 띠고 있습니다…
```

보고된 증상: 두 옵션 중 **하나만** 굵게 표시됨.

### 실제로 나온 것

```
소제목   [01. 츤데레 바니· 03
본문     덜렁이 바니] 두 모델은 **따스함이 느껴지는 오렌지 베이지 컬러**입니다.
```

모델이 잘못 읽은 것이 아니다. 강조는 본문에 정상으로 하나 붙어 있다.

### 원인 (셋이 겹쳐 있다)

**(가) 말머리를 문장으로 셌다.**
`Unit.head` 가 캡션 첫 문장을 소제목으로 올리는데, 문장 끝을 `마침표+공백`으로
찾는다. `[01. 츤데레 바니· 03. 덜렁이 바니]` 안의 `03.` 이 거기 걸려 말머리가
두 동강 났다. **대괄호 말머리는 문장이 아니다.**
→ `app/product.py` `Unit.head` / `Unit.body`

**(나) 한 유닛이 두 옵션에 걸치는 경우를 상정하지 않았다.**
`Unit.option_tag` 는 문자열 하나다. `apply_tags` 도 말머리 하나를 하나의 옵션값과
대조한다. `[02. 갸루 바니· 04. 역전 바니]` 는 어느 옵션값과도 안 맞아 태그가 안 붙고,
말머리가 본문에 그대로 남는다. 그래서 (가)에 걸렸다.
결과: 옵션 카드 4개가 전부 사진 없는 빈 카드, `옵션별로 보기` 구간 통째로 없음.
→ `app/product.py` `Unit.option_tag` · `apply_tags` · `option_groups` · `render` 옵션 구간

**(다) 엑셀과 상세페이지의 옵션명이 또 다르다.**
엑셀 `04. 역바니` vs 캡션 `04. 역전 바니`. 텐가 `복시`/`보쿠` 와 같은 종류다.
(가)(나)를 고쳐도 4번은 이름으로 안 붙는다.
→ 미해결로 남아 있는 그 문제. 순서 매칭은 한 번 넣었다가 되돌렸다(`e02a404`).

### 참고

- 엑셀 옵션값에 바코드가 붙어 있다 — `01. 츤데레 바니 - 4526374570674`
- 이 상품은 **그린**으로 떴다. 사후 게이트는 통과했고 빈 칸도 없다.
  옵션 구간이 통째로 비었는데 색으로는 안 잡혔다 — 색 규칙에 구멍이 있다는 뜻.

## #2 · 2497570 · 옐로우(유닛이 1개뿐) · 열림

**상세페이지의 상당수가 이 꼴이다.** 위에 직접 타이핑한 글이 있고(제품명·설명·주의·스펙),
그 아래 제품컷이 한두 장 덜렁. `이미지+설명 / 이미지+설명` 구조가 아니다.
텍스트가 정보고 **이미지는 구색**이다. 할 일은 적다 — 타이핑된 글을 보기 좋게 싣고,
원본 이미지는 그대로 갖다 놓으면 된다. 오히려 일거리가 줄어드는 쪽.

원본: 이미지 1장(661×1321) · 캡션 0 → 통이미지형 · **유닛 0 · 광고 1**.
그 한 장이 히어로컷으로 쓰이고 끝. 색이 옐로우로 뜬 것은 맞게 잡은 것이다.

### (가) 상품명이 어처구니없이 길다 — 간간이 나온다

엑셀 원문:

```
[일본 직수입] 갸루가 되어 돌아온 동경하는 아이라 누나의 그곳
  by 동경하는 누나가 갸루가 되어 돌아온 여름방학
  (ギャルになって帰ってきた憧れの愛良姉ちゃんのアソコ by憧れの姉ちゃんがギャルになって帰ってきた夏休み)
  - 루네기프트(GLGS0204/4582474867267) (NPR)
```

`split_name` 은 제 할 일을 했다 — 대괄호·한글명·외국어명으로 갈렸고 모델코드도 뗐다.
문제는 **한글명 자체가 두 겹**이라는 것. `by` 앞은 상품명, 뒤는 원작 만화 제목이다.
일본어 쪽도 똑같이 `by` 로 이어져 있다. 그래서 굵은 제목이 네 줄을 잡아먹고,
그 아래 작은 줄(외국어명)에도 같은 것이 한 번 더 나온다.

→ `app/render.py` `split_name`. `by` 로 자르는 규칙은 좁다 — 다른 상품에서 물릴 위험.
   판단 보류, 다른 긴 이름 사례가 더 모이면 같이 본다.

### (나) 타이핑된 글 속의 **정확한 스펙**을 못 읽는다

원본 상단에 이렇게 적혀 있다.

```
패키지 사이즈(mm): H185 × W60 × D60
본체 사이즈(mm): 125 × 60 × 60
중량: 본체 200g / 총중량 230g
```

이름표가 붙었고 어림말도 없다 — **"텍스트에 정확히 박힌 치수는 유지한다"는 그 경우다.**
그런데 스펙 줄이 비어 있다. 이유 둘:

1. `guess_specs` 가 `u.caption` 만 본다. 이 글은 `product.intro` 에 있다
2. `SPEC_RE` 는 숫자 바로 뒤에 단위가 붙기를 요구한다. `사이즈(mm): 125 × 60 × 60`
   은 단위가 괄호로 앞에 나와 있어 안 걸린다. `중량: 본체 200g` 은 형식이 맞다

→ `app/render.py` `guess_specs` · `SPEC_RE`

### (다) 타이핑 구간이 한 덩어리로 쏟아진다

둘째 문단 하나에 설명·저작권·주의 1/2/3·패키지 치수·본체 치수·중량이 전부 `<br>` 로
이어져 있다. 이 유형은 **그 글이 상품 정보의 전부**인데 읽기 힘든 채로 나간다.
주의사항은 푸터 쪽이 어울리고, 저작권 줄은 작게, 치수는 스펙 줄로 갈 자리다.

→ `app/render.py` intro 구간 · `app/source.py` `_clean_lines`

## #4 · 2497526 · 그린 · 열림

옵션 2종. 1번 옵션 설명만 굵고 크게 나오고 2번은 안 나온다.

### (가) 강조 별표가 소제목 승격을 뒤집는다 ← **새 뿌리**

`Unit.head` 는 캡션 첫 문장을 소제목으로 올린다. 조건이 `6~60자`인데,
길이를 **`**` 까지 세어** 잰다. 그래서 모델이 어디를 강조했느냐에 따라 레이아웃이 바뀐다.

```
[02. 고문교수 미즈키] 유아 타입에 비해 … 웨이브 형상이 특징인 모델입니다.
  원본             → 소제목 O
  **웨이브 형상**  → 소제목 X     ← 별표 4글자가 한도를 넘긴다
  말머리까지 떼면   → 소제목 O
```

`[01. 부부장 유아] 삽입구를 넓히면 … **미세한 돌기 무리**가 보입니다.` 도 같은 방식으로


문장은 멀쩡히 끝났다. 그런데 `app/gate.py` ③ 의 "문장을 맺는 문자" 목록이:

```python
text[-1] not in ".。!?"'’”)]'
                 └──┬──┘└──┬──┘
                 문자열1   문자열2     ← 파이썬이 둘로 읽어 이어붙인다
```

`"` 를 큰따옴표 문자열 안에 쓰려다 **거기서 리터럴이 끊겼다.** 실제 허용 집합은

둥근 `”` 로 끝났으면 통과했다. 이 원본이 곧은 `"` 를 썼을 뿐이다.

빨간불이 켜졌다. 테스트 76개는 전부 통과한다 — 곧은 따옴표로 끝나는 캡션을

### (가) "옵션값이 없으면 접두어를 그대로 믿는다" 가 틀렸다

   **"엑셀을 읽었는데 옵션이 0" 과 "엑셀이 없음" 을 구분해야 한다.**

## 2-2 · 소제목 승격 — **고침** (#1 가 · #4 가 · #12 곁다리)

`app/product.py` `Unit._split_head`. 두 가지를 고쳤다.

**(가) 대괄호 말머리 안의 마침표는 문장 끝이 아니다.**
`[01. 츤데레 바니· 03. 덜렁이 바니] 두 모델은…` 이 `03.` 에서 두 동강 나서
소제목 `[01. 츤데레 바니· 03` / 본문 `덜렁이 바니] 두 모델은…` 으로 나왔다.
이제 말머리를 건너뛰고 그 뒤에서 문장 끝을 찾는다.

**(나) 별표는 화면에 안 나오는 표시다. 길이를 잴 때 세지 않는다.**
`6~60자` 한도를 별표까지 세어 재는 바람에, 모델이 어디를 강조했느냐에 따라
소제목이 생겼다 없어졌다 했다. 옵션과 무관하게 **문장이 60자 경계의 어느 쪽에
걸렸느냐**의 문제였다.

### 실측

```
49개 회차 · 달라진 것 1개 (2497907 — 말머리가 잘리던 바로 그 상품) · 그 밖 48개 무변화
캡션 298개 중
  말머리 안에 마침표가 있는 것          6개   ← (가)가 잡는 자리
  첫 문장이 57~60자 (별표 넷에 뒤집힘)   5개   ← (나)가 잡는 자리
```

(나)는 기준선 회차에 **안 나타난다** — 기준선은 자동 채우기를 끄고 만들어 별표가
없기 때문이다. 자동 채우기를 켰을 때만 드러나므로 단위 시험으로 못 박아 두었다.
잦지는 않지만 **어느 칸이 굵어질지 예측할 수 없게** 만드는 종류라 빈도보다 나쁘다.
