# 상세페이지 자동 변환 — 설계 노트

기존 쇼핑몰(바나나몰)의 상품 상세페이지를 새 쇼핑몰(고도몰)용으로 재디자인해 옮기는 작업의
설계 기록이다. 변환 대상은 1000개가 넘고, 원본 구조에는 미리 다 알 수 없는 변형이 섞여 있다.

이 문서는 **아직 구현되지 않은 설계**를 담는다. 검증된 것과 추정인 것을 구분해 적었다.

---

## 1. 목표와 제약

- 엑셀 한 장만 업로드하면 상세페이지가 새 디자인으로 나와야 한다
- **원본 이미지는 손대지 않는다.** 이미지 안의 일본어는 제조사 원본 아트이므로 번역·재작성 대상이 아니다
- 바꾸는 것은 **배치와 텍스트 조판**이다
- 최종 출력은 HTML(SEO) — 고도몰 상세설명 필드에 들어간다
- 고도몰 등록 양식은 나중 문제다. **먼저 보여지는 상세페이지를 만들 수 있느냐**가 관건

---

## 2. 원본 데이터 구조

### 2.1 바나나몰 엑셀 (68열)

| 그룹 | 열 |
| --- | --- |
| 식별 | 상품번호 · 상품명 · 바코드 · 브랜드 · 거래처 |
| 상태 | 판매여부 · 진열여부 · 등록일 · 오픈일 |
| 가격 | 원가 · 판매가 |
| 옵션 | 옵션1~3 — `옵션명=값,값,값` 형식 |
| 이미지 | 목록이미지url · 대표이미지url · 상품url |
| 분류 | 카테고리 · 카테고리(대/중/소) |
| **본문** | **상세설명 = HTML 통짜 한 셀** |
| 스펙 | AA~BP 44열 |

**스펙 44열은 헤더가 중복된다.** `삽입길이`가 5번, `최대직경`이 5번 나온다. 카테고리별 스펙
슬롯을 한 시트에 옆으로 늘어놓은 구조라, 상품 하나는 자기 카테고리 구간만 채우고 나머지는 빈다.
확보한 샘플 5건은 모두 스펙이 비어 있었다.

### 2.2 상세설명 HTML — 두 세대

| | 구형 | 신형 |
| --- | --- | --- |
| 마크업 | `<table width="550">` 중첩 | `div.detail > .title/.desc/.desc_table` |
| 등록 시기 | 2013년경 | 2017년 이후 |
| 예 | 트리니티 · 버진루프 | 닛포리 · 텐가 · SI-X |

구형 둘(트리니티 2399106 / 버진루프 2397308)은 **공용 이미지 5장이 파일명까지 동일하고,
같은 깨진 URL(`saunpumnonex.jpgx.jpg`)까지 공유한다.** 같은 템플릿에서 찍어낸 것이다.

### 2.3 이미지 경로는 세 갈래 — 두 갈래가 아니다 ⚠️

샘플 5건 전수 조사 결과다.

| 경로 | 정체 | 처리 |
| --- | --- | --- |
| `banana_img/conf/img/…` | 공용 머리띠·배너 | 버림 |
| `banana_img/k/kimtop.jpg` | 공용 장식 | 버림 |
| **`banana_img/product_image/…`** | **상품 이미지** | **유지** |
| `files/goodsm/<번호>/…` | 상품 이미지 | 유지 |

`banana_img/`를 통째로 버리면 **텐가는 소재가 0장이 된다** — 본문 이미지가
`banana_img/product_image/man/2439903_detail_20180720.jpg` 하나뿐이기 때문이다.

### 2.4 기타 관찰

- `files/goodsm/<번호>` 의 번호가 상품번호와 다를 수 있다. 닛포리(2481433)의 상세 이미지는
  `goodsm/2478489/` 에 있다. **상품번호로 이미지 URL을 유추하면 안 된다**
- 원본 HTML에는 깨진 URL, `&nbsp;` 도배, 빈 `<p>`, CSS 값 자리에 박힌 이미지 경로
  (`style="clear:/conf/img/saunpumnonex.jpg"`) 같은 오염이 있다. 세정이 선행돼야 한다

## 3. 핵심 설계 — 페이지 유형을 분류하지 않는다

변환 대상마다 케이스를 나누면 조합이 폭발한다. 실제로 그렇게 만들었다가
버진루프에서 "상단 광고컷을 먼저 찾는다"는 전제가 깨져 예외 규칙을 덧붙이게 됐다.

대신 **모든 원본을 하나의 정규형으로 환원**한다.

```
Product
├ meta    상품명 · 브랜드 · 가격 · 옵션 · 카테고리      ← 엑셀
├ lead    리드 텍스트                                  ← 상세설명 HTML
└ units[]  { image, caption?, optionTag? }
```

확보한 사례를 이 형태로 환원하면 이렇다.

| 상품 | 유닛 | 캡션 없는 유닛 | 캡션 있는 유닛 | 옵션 |
| --- | ---: | ---: | ---: | ---: |
| 트리니티 | N | N | 0 | — |
| 닛포리 | 19 | 1 | 18 | 3 |
| 버진루프 | 7 | **0** | 7 | — |
| 텐가 | N | ? | ? | 6 |

**"광고컷이 없다"는 캡션 없는 유닛이 0개라는 뜻**이고, 그건 반복문이 0번 도는 것이지 예외가 아니다.
규칙을 추가할 자리 자체가 사라진다.

원본이 1열인지 2열인지도 읽을 필요가 없다. 어차피 새로 배치한다.

### 3.1 광고컷을 판정하지 말고 캡션 유무를 관측한다

`이건 광고컷인가?`는 판정이라 틀릴 수 있고, `캡션이 붙어 있나?`는 관측이라 틀릴 수 없다.

- 캡션 없는 이미지 → 풀블리드로 크게 (광고컷이 알아서 여기 간다)
- 캡션 있는 이미지 → 캡션 블록으로

보조 규칙 하나면 충분하다 — **본문 시작부터 캡션 없는 이미지가 연속되는 구간이 상단 광고 구간,
첫 캡션이 나오는 지점부터 설명 구간.** 순서만 보면 된다.

닛포리는 이것만으로 픽셀을 한 번도 보지 않고 풀린다. HTML이 답을 갖고 있다.

```html
<div><img _0.jpg></div>                         <!-- <span> 없음 → 광고컷 -->
<ul><li><img _1.jpg><span>캡션…</span></li>      <!-- <span> 있음 → 설명 유닛 -->
```

**라인·테두리 검출은 쓰지 않는다.** 테두리는 디자인 선택이라 색·두께·유무가 제각각이지만,
캡션은 정보라서 반드시 존재한다.

### 3.2 어댑터는 유닛 배열을 얻는 곳에만 둔다

```
엑셀 ─┬─ meta
      ├─ lead
      └─ units[] ← 어댑터가 갈리는 유일한 지점
                   ├ 조각형   : HTML 파싱          (닛포리)
                   └ 통이미지형: 분할              (트리니티 · 버진루프 · 텐가)
                            ↓
                    렌더러 · 디자인 (불변)
```

새 변형을 만나면 **어댑터만 추가한다.** 렌더러와 디자인은 건드리지 않는다.
어댑터끼리는 조합되지 않으므로 10개가 늘어도 10개로 끝난다.

어댑터 선택도 판정이 아니라 **세기**로 한다 — 상품 이미지가 2장 이상이면 조각형, 1장이면 통이미지형.

## 4. 통이미지 분할

유일하게 남는 어려운 지점이다.

### 4.1 방침 — 과분할은 허용하고 미분할은 막는다

서로 다른 조각이 한 덩이로 붙으면 되돌릴 수 없지만, 과하게 잘린 건 다음 단계에서 다시 묶을 수 있다.
그래서 경계 재현율을 우선하고 오탐은 감수한다.

### 4.2 좌표는 알고리즘이, 의미는 비전이

픽셀 알고리즘은 좌표가 정확하지만 의미를 모르고, 비전 모델은 의미를 알지만 좌표가 부정확하다.

1. 알고리즘이 통이미지를 과하게 잘라 조각에 **번호**를 붙인다
2. 번호 찍힌 조각을 한 판(컨택트시트)에 놓고 비전에 보여준다
3. 비전은 좌표가 아니라 **번호로** 답한다 — "0~3번은 광고컷 하나로 묶어라 / 4·5번은 설명 유닛"

비전이 좌표를 만들지 않으므로 좌표 오차가 원천적으로 사라진다.
그리고 광고컷 판정은 **문서 내 위치**가 필요하므로(상단에 붙는 것이 정의의 일부),
조각을 하나씩 따로 묻지 말고 전체를 한 번에 보여줘야 한다.

### 4.3 캡션 귀속은 간격으로 정한다 — ✅ 실측 검증됨

캡션이 이미지 위인지 아래인지는 디자인마다 다르다. 규칙으로 박으면 깨진다.
대신 **간격이 두 무리로 갈린다**는 성질을 쓴다.

텐가 원본(373×2000으로 축소된 상태)에 실제로 돌린 결과:

```
좁은 간격  18개   평균 2.1px   최대 4px      → 같은 유닛 (이미지↔캡션)
넓은 간격   9개   평균 12.1px  최소 7px      → 유닛 경계
           ─────────────────────────────
           4px ~ 7px 사이가 완전히 비어 있음 → 겹침 0
```

임계값을 사람이 정하지 않았다. 데이터가 스스로 두 무리로 갈렸고 그 사이에 아무 값도 없다.
**절대 임계값을 박지 말고 그 이미지 안의 상대 분포로 가른다.** 페이지마다 여백 크기가 달라도
"이 페이지 안에서 좁냐 넓냐"는 항상 갈린다.

상단 흰 배경 구간의 실제 수열:

```
y 201~356  이미지        gap  1px  ← 붙음
y 357~414  텍스트        gap  9px  ←── 벌어짐
y 423~555  이미지        gap 14px  ←── 벌어짐
y 569~578  텍스트        gap 12px  ←── 벌어짐
```

### 4.4 현재 분할기의 알려진 결함 ❌

`slicer/`(스크래치)에 합성 이미지로 경계 재현율 8/8을 달성한 구현이 있으나,
**실제 파일 첫 접촉에서 두 군데가 깨졌다.**

1. **어두운 배경 구간에서 밴드 검출 실패** — 배경 판정이 흰색 기준이라, 텐가 하단 흑백 섹션에서
   콘텐츠와 배경을 못 가르고 전부 한 덩이로 뭉쳤다
2. **2열 구간을 가로 스캔만으로 처리** — 좌우 두 칸이 같은 행을 공유해 한 밴드로 섞인다.
   어느 캡션이 어느 이미지 것인지 가로 스캔으로는 알 수 없다

텐가 변환 실패도 정확히 같은 지점에서 같은 이유로 났다. 상단 그리드까지는 멀쩡하다가
2열 구간부터 캡션이 한 칸 밀렸다.

**고칠 순서:**

```
1. 배경색 구간을 먼저 나눈다 (밝음/어두움) → 구간마다 배경색을 따로 잡는다
2. 각 구간에서 2열인지 보고 세로로 가른다
3. 열별로 간격 이중구조를 적용해 캡션을 귀속시킨다
```

지금까지 만든 것은 3번뿐이고 1·2번이 통째로 빠져 있다.

> ⚠️ 위 실측 수치는 **373×2000으로 축소된 파일**에서 나왔다. 원본은 폭 600px 정도다.
> 임계값을 확정하려면 원본 화질로 다시 재야 한다.

## 5. 1000개를 안전하게 굴리는 법

케이스를 미리 다 수집할 수는 없다. 대신 **결과물이 만족해야 할 성질**을 정의한다.
케이스는 무한하지만 불변식은 유한하다.

### 5.1 불변식

| | 검사 | 잡히는 것 |
| --- | --- | --- |
| ① | 원본 통이미지 면적 ≈ 배치된 조각 면적 합 | 잘림 |
| ② | HTML 이미지 수 = 배치된 이미지 수 / 캡션 수도 동일 | 누락 · 중복 |
| ③ | 캡션이 문장 중간에 끊기지 않음 | 잘린 캡션 |
| ④ | 조각의 종횡비·최소 크기가 정상 범위 | 분할 실패 |
| ⑤ | 캡션 수 ≤ 이미지 수, 옵션 수 ≤ 배분 가능 유닛 수 | 매핑 불가 |
| ⑥ | **유닛 안 간격 < 유닛 사이 간격** | **묶음 오류** |

⑥이 없으면 텐가의 "캡션 한 칸 밀림"을 못 잡는다. 조각이 다 살아 있고 묶음만 틀렸으므로
①(면적 보존)을 통과해 버린다.

### 5.2 게이트는 두 겹

**사전 게이트 — 엑셀만 보고, 이미지를 받기 전에.** 비용이 0이다.

- 상품 이미지 0장 → 보류
- 이미지 6장 이상 && 캡션 0개 → 보류
- 옵션 수 > 배분 가능 유닛 수 → 보류

**사후 검증 — 변환 후 불변식 6개.** 위반하면 결과물을 폐기하고 보류 풀로 보낸다.

### 5.3 보류 사유 코드가 변수를 대신 수집한다

```
NO_BODY_IMAGE          본문 이미지 없음
NO_CAPTION_MULTI_IMG   이미지 다수 + 캡션 0
AREA_LOSS              면적 손실 임계 초과
CAPTION_TRUNCATED      캡션 문장이 끊김
PANEL_GEOMETRY         조각 기하 이상
PROXIMITY_INVERTED     유닛 안 간격이 유닛 사이보다 큼
OPTION_UNMAPPABLE      옵션을 유닛에 배분 불가
```

1000개를 돌리고 사유별로 집계하면 그것이 곧 변수 목록이다.
`NO_CAPTION_MULTI_IMG 120건`이면 그게 다음에 만들 어댑터고, 3건짜리 사유는 손으로 하면 된다.
**어댑터 개발 우선순위가 데이터로 정해진다.**

### 5.4 규칙을 느슨하게 하지 않는다

- 느슨한 규칙 → 애매한 것도 통과 → 엉터리 결과가 조용히 섞인다
- 엄격한 규칙 + 불통과 시 보류 → 통과한 건 확실히 맞다

**엄격함은 유지하고 실패를 허용한다.** 600개 통과 / 400개 보류가,
1000개 변환 후 300개가 조용히 망가진 상태보다 낫다. 보류는 실패가 아니라 정상 동작이다.

### 5.5 실행 순서

1. 사전 게이트로 전량 스캔 (비용 0)
2. 쉬운 것부터 — 조각형 + 캡션 짝 있음(닛포리류)
3. 통이미지형 — 분할 + 불변식 검증
4. 보류 풀 집계 → 상위 2~3개 사유만 어댑터 추가 → 재실행

## 6. 새 디자인 — 골격과 차별화

### 6.1 조건부 섹션 골격

```
① 히어로        대표이미지 + 상품명 + 브랜드 + 리드 한 줄
② 스펙 요약     수치 3~6개 가로 배열              [스펙 있을 때]
③ 리드 문단     HTML 카피 + 강조                  [카피 있을 때]
④ 옵션 가이드   옵션별 카드                        [옵션 있을 때]
⑤ 디테일 섹션   ← 유닛이 여기로 (본체)
⑥ 스펙표                                          [스펙 있을 때]
⑦ 공통 푸터     배송 · 교환 · 주의사항
```

②와 ⑥은 원본에 없던 구조다. **원본에 없던 것을 추가하는 것이 가장 강한 차별화**이며,
정보 품질도 함께 올라간다.

### 6.2 판정이 필요 없는 차별화 레버

전부 순서와 개수만으로 결정되므로 판정 부담이 늘지 않는다.

1. **리듬 변주** — 일률 2열 대신 `1열 크게 / 2열 / 2열 / 1열 크게`
2. **첫 유닛 승격** — 각 섹션 첫 이미지를 히어로 크기로
3. **좌우 교차** — 짝수는 이미지 좌, 홀수는 우
4. **큰 번호** — `01 02 03`
5. **캡션 첫 문장 승격** — 첫 문장을 소제목으로, 나머지는 본문

5번은 효과 대비 비용이 가장 낮다. 캡션이 이미 `압권의 패키지 퀄리티. AV 여배우를…` 처럼
첫 문장이 요약인 구조라, 마침표로 자르기만 하면 소제목이 나온다.

기존 변환본이 "확 달라 보이지 않는" 이유는 바꾼 것이 전부 **덧붙이기**(헤더·배지·푸터)라
원본의 **배치 리듬**이 그대로이기 때문이다. 사람은 색이나 폰트보다 리듬으로 페이지를 구별한다.

### 6.3 폭 — 미결

원본 이미지가 550~565px폭이라 넓은 페이지에서 늘리면 뭉갠다.
2열 그리드로 가면 셀이 ~450px이라 오히려 축소되어 선명해지고, 원본의 1열 나열과도 달라진다.
**아직 결정되지 않았다.**

## 7. 사례별 진단

| 상품 | 번호 | 구조 | 판정 |
| --- | --- | --- | --- |
| 트리니티 | 2399106 | 통이미지 1장 · 캡션 이미지 내부 · 옵션 없음 | 분할 필요 |
| 버진루프 | 2397308 | 통이미지 1장 · `[이미지][캡션]` × 7 · 1열 | **변환 성공** |
| 닛포리 | 2481433 | 통 히어로 1 + 조각 18 + 캡션 18 · 옵션 3 | **변환 성공** |
| 텐가 | — | 통이미지 1장 · 옵션 6 | **실패 — 캡션 한 칸 밀림** |
| SI-X | 2419001 | 이미지 9장 · 캡션 0 · 옵션 10 | **실패 — 보류가 정답** |

### SI-X는 어댑터를 만들 대상이 아니다

이미지 9장 · 캡션 0개 · 옵션 10종의 세 숫자가 서로 맞지 않는다.
이미지를 옵션에 배분할 근거가 파일명에도 HTML에도 없고, 각 이미지가 그 자체로 또 통이미지다.
정규형으로 환원되지 않으므로 무슨 규칙을 붙여도 추측이 된다.
**엑셀만 보고 사전 게이트에서 걸러야 한다.**

### 버진루프의 첫 유닛에는 테두리가 없다

2~7번 유닛은 테두리 박스지만 첫 유닛만 없다. 테두리 기준이면 여기서 이미 깨진다.
반면 캡션은 7개 전부에 예외 없이 있다. 4.1의 근거다.

### 옵션 태그는 캡션 접두어에서 온다

닛포리 캡션은 `[01. 키타노 미나] …`, 텐가 캡션은 `[웨이비 2] …` 로 시작하고
둘 다 엑셀 옵션값과 정확히 대응한다.

**닛포리는 HTML 텍스트, 텐가는 통이미지 OCR 텍스트인데 규칙은 하나로 통한다.**
어댑터가 무엇이든 유닛 배열만 나오면 그다음은 공통이라는 근거다.

값을 옮길 때 원본 접두 번호(`01. `)를 벗겨야 한다. 그대로 두면 출력 쪽 번호와 겹친다.

### 교차 검증이 원본보다 품질을 올린다

- 버진루프 통이미지 캡션은 `네일 클로버 … 뻥은 구멍`, HTML 리드는 `네잎 클로버 … 뚫린 구멍`.
  원본 쇼핑몰이 이미지에 오타를 냈고 텍스트에는 제대로 썼다.
  **HTML 텍스트가 OCR 교정 사전 역할을 한다**
- 닛포리 옵션값은 `미우라 사쿠라`인데 이미지의 일본어는 `水トさくら`(미즈토)로 읽힌다.
  원본 데이터의 오류로 보인다

## 8. 출력 대상 — 고도몰 (나중 단계)

다운로드 양식은 80열이며 **확장자만 `.xls`이고 실제로는 HTML `<table>`**이다.
openpyxl/xlrd로 열리지 않으므로 전용 파서가 필요하다. 업로드 양식은 다를 수 있어 미확인.

설계에 영향을 주는 필드:

- `PC쇼핑몰상세설명` / `모바일쇼핑몰상세설명` — **분리돼 있다.** 두 벌이 필요하다
- `짧은설명` — 리드 카피 자리
- `검색키워드` — OCR로 캐낸 키워드가 여기로. SEO 직결
- `추가항목(항목:내용)` / `필수정보(항목:내용)` — 스펙을 HTML에 박지 말고 구조화 필드로
- `성인인증` — 이 카테고리는 `사용함`이어야 한다 (데모 기본값은 `사용안함`)

옵션 인코딩 (실측 확인):

```
옵션명 = 사이즈
옵션   = 1. 라지//0원/1,000원/222//노출함/판매함/
      <br>2. 미디움//0원/20,000원/222//노출함/판매함/

행 구분 <br> · 필드 구분 / · 9필드
[0] 순번. 옵션값  [1] 자체코드  [2] 매입가  [3] 옵션추가금액
[4] 재고         [5] 미상      [6] 노출     [7] 판매      [8] 끝
```

`상품재고 444 = 222 + 222` 로 옵션 재고 합이 상품 재고와 일치하는 것을 확인했다.

미확인: 옵션 축이 2개 이상일 때의 인코딩, `이미지` 6슬롯의 슬롯별 의미, 다중 카테고리 구분자.

**상세설명 컬럼은 `<br>`을 구분자로 쓰지 않는다** — 이미 `<p><br></p>`가 값으로 들어 있고
고도몰이 그대로 내보낸다. HTML을 넣어도 안전하다.

## 10. 환경

클라우드 환경의 네트워크 액세스를 `신뢰됨` → `전체` 또는 `사용자 지정`으로 바꿔야 한다.
`사용자 지정`이면 아래를 넣고, **패키지 매니저 기본 목록 포함 체크를 반드시 켠다**

```
*.bizhost.kr
www.bananamall.co.kr
*.cdn-nhncommerce.com
```

환경 변경은 **새 세션부터 적용된다.**
